Two tiers, for two different questions.

- **`minimal/`** answers "is my install working, and what do the input files look
  like?" It is a complete, runnable 40-protein toy study.
- **`vendor/`** answers "I have a search engine output, how do I turn it into
  that?" It maps DIA-NN, MaxQuant, and FragPipe columns onto ProSIFT's schema.

## The minimal example

| File | What it is |
|---|---|
| `abundance.csv` | 40 proteins x 6 samples, raw intensities, with peptide counts; no extra columns |
| `metadata.csv` | `sample_id` + `condition` (3 CTRL vs 3 TREAT) |
| `params.yml` | annotated parameters, generated |
| `samplesheet.csv` | one row, relative paths |
| `example_gene_sets.gmt` | 4 gene sets built from the example's own symbols |
| `ground_truth.csv` | which proteins were spiked, and in which direction |
| `ProSIFT_input_template.xlsx` | human-facing authoring template |

The data is synthetic and generated by `generate_examples.py`. Effects are
planted in two whole functional blocks: `EXAMPLE_ASTROCYTE_MARKERS` up
(log2FC +2.5) and `EXAMPLE_MITOCHONDRIAL_RESPIRATION` down (log2FC -2.0), 18
proteins in total.

**That design is a defect, not a feature** (KNOWN_ISSUES E-5). Shifting 45% of
the matrix coordinately breaks median normalization's core assumption, which
inflates the up-block to +3.15, attenuates the down-block to -1.47, and gives
every null protein a +0.3 to +0.4 log2 bias.

**`ground_truth.csv` is wrong.** It claims 18 significant proteins; the pipeline
calls 19, because that bias pushes `P00034` over the fold-change threshold
(KNOWN_ISSUES E-6). Do not use it as an oracle.

Protein accessions (`P00001` ...) are **real UniProt entries**, not placeholders:
the `P00001`-`P00040` block is historical cytochrome c across ~40 species
(`P00001` = CYC_HUMAN, `P00009` = CYC_MOUSE). An earlier version of this file
claimed they were synthetic. They resolve, they carry the wrong gene symbols for
this example, and they overlap the shipped GMT in zero genes (KNOWN_ISSUES E-3).

### Regenerating

```bash
python assets/examples/generate_examples.py --outdir assets/examples/minimal
```

The CSVs are committed so they can be read without running Python, but they are
generated artifacts. Retune effect sizes by editing `EFFECTS` and re-running,
never by hand-editing the CSVs.

All paths are relative, so the example works from any clone location. The
GMT path in `params.yml` resolves against the `params.yml` directory, and the
workflow stages the file into the ENRICHMENT task.

## The .xlsx template

ProSIFT **cannot read .xlsx**. The workbook is an authoring aid; export its
sheets to CSV before running. Handing an `.xlsx` straight to the pipeline
currently produces a decode traceback rather than a clean error message.

Its "READ ME FIRST" sheet carries the rules, but the two that bite hardest:

- **Note *columns* are safe. Note *rows* are not.** Column selection is
  prefix-based, so anything not starting with `abundance_` or `peptide_count_`
  is ignored; the template's `abundance` sheet ships a `notes` column to
  demonstrate it. But every *row* is read as a protein, so two comment rows
  collide as duplicate IDs and fail the run.

  `minimal/abundance.csv` deliberately carries no such column: it is the
  canonical reference for what an abundance CSV should look like.
- **`input.abundance_type` is never guessed.** On `raw`, values `<= 0` become
  NaN; on `log2`/`normalized`, 0 is a legitimate value. Mislabelling log2 data
  as raw silently deletes every negative value. This is the single most
  dangerous field in the input set.

## Other things that fail the run

- Every sample with an `abundance_` column needs a matching `peptide_count_`
  column. Partial coverage is a hard error. Omitting peptide counts entirely is
  legal but silently downgrades DEqMS to unweighted.
- `sample_id` in the metadata must equal the abundance column name with the
  prefix removed, exactly.
- The separator is inferred from the file extension only: `.csv` comma,
  `.tsv`/`.txt` tab. A tab-delimited file named `.csv` fails confusingly.
- Protein groups are collapsed to the first semicolon-delimited accession.
  Duplicates after collapsing are a hard error.
